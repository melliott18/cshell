# POSIX utilities and option profiles

This inventory accompanies the [language and invocation matrix](posix-matrix.md)
and uses its status vocabulary and the [evidence conventions](posix-evidence.md).
It targets **POSIX.1-2024, Issue 8**. Rows reserve stable requirement and fixture
IDs; they do not claim that fixtures or implementations already exist. A utility
row covers its listed behavior families, with operand, option, environment,
stdout/stderr, status, error, and state-lifetime cases to be split into fixtures
by its owner. Passing one subcase never verifies the entire row.

**Base** means required within the shell target. **Conditional UP** and
**Conditional XSI** preserve the standard's option shading; neither optional
group is selected in the [current base profile](posix.md#selected-profile).
O-020 and O-021 record the decision. **Unspecified** allows multiple results and
must not acquire a single reference-shell oracle. **Implementation-defined**
requires a documented choice and tests against that choice. **OB** marks an
obsolescent requirement, not an exemption. All requirements here remain open
unless evidence explicitly says otherwise.

## CSH-029 allocation decision

The current implementation profile is base Issue 8 shell behavior; UP and XSI
are not selected for a conformance claim. Their conditional rows remain tracked
for future profile expansion; this decision does not waive any
unshaded requirement. History/vi/mail implementation tickets must be allocated
before UP can be selected, as required by O-022–O-024.

All 15 special builtins are internal. The exact intended intrinsic set is the
16 standard names in U-017–U-032; no extra intrinsic names are added. `pwd` is
an internal regular builtin, also available as a host executable. [CSH-031](evaluation-builtins.md) supplies
PATH/function precedence and intrinsic lookup integration. `printf`,
`echo`, `test`, `[`, `true`, and `false`, plus all other standard utilities in
U-034, use host executables. CSH-031 owns their lookup/integration fixtures;
CSH-037 records executable availability and platform behavior. `kill` needs both
internal job-aware handling and an exec-accessible host implementation.
Every row below retains its owner and evidence target; allocation is not evidence
that the utility passes. In particular, `read`, `getopts`, `hash`, `umask`,
`times`, and base `ulimit` are implemented internally by CSH-031. Exit remains with
CSH-018/035 and the existing CSH-019 handler, without a duplicate implementation.

State-module evidence for U-002, U-009–U-013, U-016 (variables), U-019 and U-033
is `make test-builtins`, described in [State builtins](state-builtins.md).
U-001 has prepared assignment and redirection-failure coverage there. Full
syntax/expansion, function removal, runtime errors and option interactions now
have selected CSH-023/028/031/032 witnesses. Complete family evidence remains
open under CSH-047–CSH-051; these rows are not fully verified.

## Intrinsic utilities

[XCU 1.7](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap01.html#tag_18_07)
names exactly the following 16 utilities. They bypass PATH lookup when applicable;
being listed as intrinsic does not remove the UP/XSI condition on an individual
utility. Additional intrinsic names would be an implementation-defined extension;
CSH-029 must document any proposal and its lookup consequences before acceptance.
`kill` uniquely still needs an exec-accessible implementation under
[XCU 1.6](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap01.html#tag_18_06).
The shell owns intrinsic behavior; a host executable alone cannot implement
changes to the current shell environment.
