## Goal

Make the interactive prompt after `bg` reliable under the Linux PTY suite.

## Scope

- Reproduce or isolate the intermittent `Ctrl-Z jobs bg fg Ctrl-C` failure in
  [`tests/jobs_cases.py`](../../tests/jobs_cases.py), especially after the job
  reports `Running` but the next primary prompt does not appear.
- Determine whether the shell stalls, the harness misses output, or host load
  exceeds the fixture deadline. Preserve exact PTY output and process-group
  assertions; do not turn a genuine shell stall into a passing skip.
- Add a timing-independent regression or a bounded stress fixture for the
  confirmed cause. Keep terminal and child cleanup checks intact.

## Acceptance criteria

- [x] The root cause is identified with a bounded reproducer and a failing
  pre-fix observation.
- [x] The fix passes repeated native Ubuntu and Docker PTY checks, including
  ASan/UBSan, with no hidden deadline or output relaxation.
- [x] The [JOB-002](../posix-matrix.md#job-002) and
  [JOB-003](../posix-matrix.md#job-003) evidence records are updated.

## Validation

## Implementation notes/evidence

The first CSH-037 push failed in the Ubuntu 24.04/GCC job of
[run 36156253758](https://github.com/melliott18/cshell/actions/runs/36156253758).
The shell printed `[1]+ Running ... hold\n` after `bg`, but the expected `$ `
prompt did not appear within five seconds. Session cleanup killed the shell.
The same revision passed in the second Ubuntu job of
[run 36156295337](https://github.com/melliott18/cshell/actions/runs/36156295337).
Mac and local Docker PTY runs passed this case. The cause remains unknown.

### Diagnosis and correction, 2026-09-26

This failure also recurred at `8f86226` in
[run 36160489602](https://github.com/melliott18/cshell/actions/runs/36160489602).
The follow-up work starts from merged `58ca5c3` on
`test/CSH-037-audit-follow-up`. Its code prerequisite is CSH-034; CSH-037 is
the discovery/audit owner, not a prerequisite that prevents fixing its findings.

The unmodified Docker scenario failed at repetition 28. A diagnostic build
then captured `fputs=-1`, `errno=EINTR`, and a successful `fflush`; the shell
was sleeping in `pselect` (`/proc/.../wchan` reported `do_select`). The
`SIGCHLD` generated by resuming the child interrupted the unchecked prompt
write. The shell had proceeded to read input with no visible prompt.

[`src/main.c`](../../src/main.c) now writes prompts through the existing
`csh_write_text` helper, which retries interrupted and partial writes.
[`tests/prompt_faults.c`](../../tests/prompt_faults.c) deterministically injects
both faults into primary and continuation prompts. The old implementation
fails its exact transcript and fault-count assertions; `make test-prompt`
passes with the fix and is part of `make test`.

The job PTY suite adds 32 complete stop/bg/fg/Ctrl-C cycles with exact bytes,
exit status and foreground-group assertions under the existing five-second
case bound. Each cycle ends the job before starting another, avoiding a test
race between a second Ctrl-Z and the preceding `fg` continuation.

Recorded validation:

- Native macOS normal build: prompt fault regression, all 13 job PTY cases,
  terminal failure cleanup, and the full `make -j2 test test-pty test-harness`
  passed.
- Docker Linux aarch64: the original scenario passed 1,000/1,000 repetitions;
  the new 32-cycle case fails the unmodified implementation at its first job.
  The fixed full normal suite passed, including 13 job PTY cases.
- The fixed 32-cycle case passed with default ASan/UBSan once. Supplemental
  ASan/UBSan stress with `detect_leaks=0` passed 200/200 cases (6,400 resumes).
  This supplemental result does not replace the default sanitizer gate. An
  earlier long stress run with LeakSanitizer enabled timed out at process exit
  after the complete expected transcript, with the process stopped under the
  LeakSanitizer tracer; it was not counted as a passing default-sanitizer run.
- Independent code review found no actionable issue. Final hosted repetition
  and the integrated sanitizer result are recorded in the CSH-037 follow-up.

Full jobs/signal requirement-family coverage remains an explicit limitation
under [CSH-050](CSH-050-jobs-signals-evidence.md).

### Repeating the real PTY scenario

After building `cshell` and `build/tests/jobs-pty.json`, run from the repository
root (or from `/work` in the Docker image):

```sh
python3 - <<'PY'
import json
from pathlib import Path
import sys
sys.path.insert(0, 'tests')
import smoke
suite = json.loads(Path('build/tests/jobs-pty.json').read_text())
case = next(c for c in suite['cases'] if c['name'] == 'Ctrl-Z jobs bg fg Ctrl-C')
for iteration in range(1000):
    failures = smoke.run_case(Path('cshell').resolve(), case, 5, 65536)
    assert not failures, (iteration, failures)
print('1000 exact PTY cases passed')
PY
```

The historical pre-fix reproduction used the image
`sha256:bad5f5f41570295ed615acf54f44791b7d7458b8c1ce632aaa2314613415a492`
containing the old prompt path. A fresh build of `58ca5c3` reproduces that source;
signal-race iteration counts depend on scheduling. The deterministic fault
fixture supplies the stable regression independently of that timing.


The integrated source `41c2eb6` passed full native macOS ASan/UBSan and
[all hosted native Ubuntu, macOS 15 and Docker jobs](https://github.com/melliott18/cshell/actions/runs/36217674357),
including sanitizer stages. See the [CSH-037 run record](CSH-037-portability-audit.md#integrated-follow-up-validation)
for identities and counts. The ticket is ready for review and remains `review`
until integration.
