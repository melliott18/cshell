# Requirements by owning ticket

Use this reverse index with the [language/invocation matrix](posix-matrix.md),
[utilities and options](posix-utilities.md), and [evidence conventions](posix-evidence.md).
Each requirement link lands on its source, scope, intended fixture and current
evidence; each requirement row links back to its owners. A ticket appearing here
has assigned work, not verified behavior. Shared rows require integration between
all listed owners. Planned fixture IDs become actual test links in the same rows
when implemented.

Maintain this index whenever an owner changes or a row is split. Include every
owner named in a requirement table's owner cell. Scope decision coordinators
must allocate new linked implementation tickets before claiming the work is
covered by an existing ticket.

## Supporting and audit tickets

- [CSH-001](tickets/CSH-001-project-foundation.md) provides the baseline build and
  smoke records. Its completion does not verify language requirements.
- [CSH-017](tickets/CSH-017-test-harness-and-ci.md) implements the shared fixture
  infrastructure for all rows. Harness self-checks are separate from shell cases.
- [CSH-033](tickets/CSH-033-pty-test-harness.md) provides terminal infrastructure
  in addition to the PTY requirements explicitly assigned above.
- [CSH-036](tickets/CSH-036-conformance-matrix.md) establishes and reviews this
  inventory; implementation tickets maintain it as their work lands.
- [CSH-037](tickets/CSH-037-portability-audit.md) audits every row across supported
  platforms, including rows not explicitly listing it as an implementation owner.
- [CSH-012](tickets/CSH-012-conformance-and-portability.md) remains the parent
  milestone. This baseline does not complete it or any behavioral milestone.

owners in the [choice register](posix-matrix.md#open-implementation-choices).
