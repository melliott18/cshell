# Shell state and builtin evidence

[CSH-048](tickets/CSH-048-state-builtin-evidence.md) reviews the 24 families below
against POSIX.1-2024. This inventory maps individual conditions to executable
assertions; it does not promote an entire family to verified from selected
witnesses. The [run records](#run-records) identify tested source and binaries.

S/P/E/R/C/O/T use the bounded shared runner with isolated HOME/TMPDIR, PATH from
`os.defpath`, LANG/LC_ALL=C (unless overridden explicitly), umask 077, fresh cwd,
five-second deadline, 65,536-byte captured output bound, and process-group
cleanup. P also sets TZ=UTC0. P checks status 0, empty stderr and no runner
failures **in addition** to its stdout predicate. Limit mutations occur only
inside disposable shell children; the test runner's limits are unchanged.
`state_builtin_helper.c` burns 0.15 CPU seconds or reports actual `getrlimit`
values, independently of cshell formatting. API evidence never substitutes for
runtime coverage. Host printf/cat/test/mkdir/ln supply fixture operations, not
oracles for shell semantics.

Exact cshell diagnostic wording and chosen nonzero statuses are regression
assertions. Unless explicitly specified, the normative contract is a diagnostic
and the required status class/consequence, not that wording. No reference shell
was used to derive expectations. E's historical exact hash lines and numeric
umask spelling are project regression choices; P/S add format-independent
invariants and reinput tests instead of treating those spellings as portable.

For U-001's utility-syntax partition, dot, exec, export, readonly and unset
claim the syntax guidelines (dot excepts the utility-name guidelines); set
adds its explicit + and -- rules. Colon, eval, return, shift and times do not
claim those guidelines: accepting an initial -- for some of them is a project
extension, not a blanket POSIX requirement. Error consequences still follow
§2.8.1 and each utility's specific exceptions.

## State and startup

[`main.c`](../src/main.c) invokes `csh_builtin_initialize()` from
[`builtin.c`](../src/builtin.c) before parsing. Raw `csh_state_create()` remains a
storage API: it deliberately does not reset imported values. The runtime now
resets IFS/PPID/OPTIND and validates/initializes PWD. [`execute.c`](../src/execute.c)
owns execution contexts and temporary variable scopes.

## Additional runtime partitions (2026-09-28)

The initial map's catch-all requests for every permutation are refined into the
following observable conditions. Matrix families remain **implemented subset**;
passing these conditions does not waive unknown cases or the CSH-012 gate.
Signal/trap timing, broader expansion/option interactions and host qualification
retain CSH-054, CSH-047/051 and CSH-060 respectively. No new profile exclusion is
introduced. F permission cases require a non-root runner; both recorded native
and Docker runs provide it. Startup allocation and syscall tests use the public
entry point with narrowly instrumented objects, not the unmodified production
binary; S/P and capability cases use the production binary.

| Conditions / rows | Exact new assertions and classification |
| --- | --- |
| U-027 last-variable remainder | S `read one trailing separator`, `only separator`, `last trailing separator`, `last empty field`, `mixed trailing whitespace`, `escaped trailing whitespace`, `repeated operand clears`, `empty IFS extra operands` check exact values. Issue 8 requires the last variable to receive the unsplit remainder minus only IFS whitespace. The old UTF-8 single-trailing-delimiter expectation was corrected to retain `é`. |
| U-027 ordered assignment errors | S `read ordered assignment b` / `1bad` checks earlier assignment, unchanged failing/later variables, status 2 and that the entire input line was consumed; a second read must get the next line. `read EOF ordered assignment` distinguishes an assignment error from EOF status 1. Stopping after the failing operand is the permitted policy. |
| U-001/009/010/012/014 output errors | S names `<utility> output failure suppressed`, `fatal`, `interactive`, for `export -p`, `readonly -p`, `set`, `times`, assert stderr, status, no post-fatal file, and recovery where required. Malformed raw envp, error publish ordering, invalid operands outside the synopsis,
and selected nonzero diagnostic numbers are robustness/policy regressions.
They are not requirements imposed on other shells. Exhausting initialization
allocations checks the implementation's failure contract and sanitizer cleanup;
it does not assert behavior under arbitrary system-wide resource exhaustion.
